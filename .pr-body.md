## The browser was the missing gate

Every check in this repo until now read source or the prerendered marketing page. The dashboard and the editor — the two screens the product *is* — had never been opened by anything.

This PR is what happened when one was. It runs Chrome (Playwright, `channel: "chrome"` — this host has no bundled Chromium) against `next dev` plus `wrangler dev` on port 4100, with the dev auth bypass on, driving the seeded documents end to end.

The harness is committed under `scripts/probe/` so the next pass starts where this one finished. `full-pass.cjs` is 8 checks: keyboard access, preview rendering, three export formats, review findings, and horizontal overflow at 390px on both screens.

---

## 1. No resume was ever exported in the font it asked for

The worst one, and it had been true for the entire life of the feature.

`loadFontFamily` fetched the font bytes correctly and then called `$typst.addFonts([buf])`. **That method does not exist.** It threw, the surrounding `catch` logged `console.warn`, and the compiler carried on with Typst's built-in face. Every export embedded LibertinusSerif regardless of what the user chose.

Worse, the substitution table only decided *which file to download*. The document still named the requested family — `"Times New Roman"`, which Typst does not have — so Typst picked its own fallback and the file it had just fetched went unread. The app's careful "preserve the generic family" logic had never influenced a single PDF.

Fixes, in order of dependency:

- **Register fonts the supported way.** `loadFonts([...urls])` in `beforeBuild`. The lazy `setFonts` path needs a `FontInfo` descriptor the library only produces internally — `{ family }` gave `expected a sequence`, `[family]` gave `expected struct FontInfo`, `[{ family }]` gave `missing field variant`. `loadFonts` with URLs is the documented path for "fonts it has no metadata for", and it works.
- **Resolve the family into the document.** `serializeSettings` now emits `resolveTypstFont(...).typstFamily`, so the file that was loaded is the family that is asked for.
- **Substitute on metrics, not taste.** `Times New Roman → Tinos`, `Arial`/`Helvetica → Arimo`, `Calibri → Carlito` — the clones built to the same advance widths. Previously Times resolved to a Computer Modern serif and Arial to Inter, so a two-page resume could spill to three in Word. Georgia and Garamond stay on the built-in serif because no metric-compatible free equivalent exists.

Verified by exporting all four seeded resumes and reading the embedded font out of each PDF:

```
Harvard Application              48639b  ["Tinos-Bold","Tinos-Regular"]
Senior Software Engineer — …     35131b  ["Inter-Regular"]
Product Engineer — Full Stack    30116b  ["Inter-Regular"]
Consulting — Strategy & Ops      27081b  ["Inter-Regular"]
```

## 2. `dateFormat` was a setting that did nothing

Offered in the UI as a four-way choice, present in the schema, read by nothing. A resume set to `MMM YYYY` printed `2020-09 - 2024-05` in the PDF and the preview.

One formatter (`src/lib/format-date.ts`) now feeds the Typst serialiser, the HTML preview and the plain-text export — three copies would have been three chances to disagree. The preview above shows `Jun 2023 - Aug 2023`.

## 3. The plain-text layer described a document nobody could produce

It emitted `Object.entries(item)`:

```
institution: Harvard University
degree: Bachelor of Science in Computer Science
startDate: 2020-09
achievements: Dean's List (All Semesters),Teaching Assistant for CS50
```

Internal field names leaked into a user-facing artefact, arrays lost their comma spacing, and — the serious part — **it did not match the PDF**. The product's central claim is that this text is what a parser reads out of the document. Each section now renders the way its template draws it, in the template's order, and empty sections are skipped instead of printing a heading with nothing under it.

## 4. Opening a resume did not change the URL

Next's App Router replaced the URL with `/app/` about **876ms** after any in-app navigation, deleting the fragment. Confirmed from a stack trace: `next/dist/client/components/app-router.js` calling `History.replaceState`.

Consequences, all live: the open document was not linkable, a reload dropped you on the dashboard, and back/forward had nothing to move between.

- Navigate with `history.pushState` — it fires no event, so Next never sees it.
- Re-assert the fragment when Next `replaceState`s its canonical route, via the **native** method captured before Next patches `history`. Routing the correction back through Next's patched version made it dispatch a router action, and during hydration that threw `Router action dispatched before initialization` — a blank editor on a cold deep link.

This also surfaced a latent bug: `replace()` had two identical branches (`? `/${to}` : `/${to}`), so the root redirect wrote `#//dashboard` — a path no route matches. Invisible while Next was deleting the fragment.

Verified: dashboard → editor → reload → back → forward → cold deep link, all correct, 2 `replaceState` calls total, no runaway.

## 5. The preview clipped the document

At 100% a Letter page is 612pt × 96/72 = 816px in a ~650px panel. The wrapper centred its child, so the overflow went equally both ways and the **left half was unreachable** — the screenshot showed headings reading "tion" and "r of Science". The page is now fitted to the panel on first paint (73% at 1568px) and any explicit zoom wins from then on; `min-w-max` keeps a zoomed page fully scrollable.

## 6. Two accessibility defects on the dashboard

- The primary action — open a resume — was a `<div onClick>`: not in the tab order, no accessible name. The card title is now the control (its own text is the name) and the preview is a `tabIndex={-1}` pointer-only duplicate.
- The card's ⋯ menu had no accessible name. Now `Actions for <resume name>`.

## 7. The bullet review collapsed every entry in a section

`collectBulletFindings` pushed one finding per entry but hardcoded `index: 0`, and the panel keyed on `sectionId` alone. Two roles in one section produced two findings with the same identity — React logged `Encountered two children with the same key, sec-exp` — and rendered as two unlabelled blocks of bullets with no way to tell which job they came from. Findings now carry the entry's real index and its label; the panel heads each block with the company.

## Also

- **Typst's own default fonts are served from this origin.** They are the substitution target for any family we do not ship, and the library fetched 17 of them from jsDelivr on every first compile. `assetUrlPrefix` now points at `public/fonts/typst/`. (An earlier attempt passed `assets: false` to the init options — a key that is not part of `InitOptions`, so it was ignored while a test asserting the string sat green. That test now asserts the loader and the prefix.)
