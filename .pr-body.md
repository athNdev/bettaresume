## What

Closes the live remainder of `[CLEAN] Wire or remove the controls that silently do nothing` (the rest of that item's table was already fixed by earlier PRs — `resume.createVariation`, the three real templates, the import review gate, `SyncManager`, and the hardcoded activity log are all gone).

### `settings.layout`

`resumeSettingsSchema.layout` accepted `"single-column" | "two-column" | "sidebar"`, `preview.tsx` faithfully drew two-column and sidebar, and **no Typst template ever read it**. A user could pick "Sidebar", watch the preview reflow, and export a single-column PDF.

The previous fix kept the field, kept the dropdown, and offered exactly one option — "Single column" — while the preview ignored the value. That is the same broken promise with less code: a control you can click that cannot change anything.

### `showIcons`

Stored, defaulted, serialised into the Typst payload, read by nothing. Its absence is also deliberate: icons in a section heading are a parse hazard, which is why no template draws them.

## Removed

| Thing | Why |
|---|---|
| `settings.layout`, `settings.showIcons` (type + Zod) | no reader |
| the Layout `<Select>` in the formatting toolbar | one option, no effect |
| `checkLayout` + its rubric check `layout-single-column` | only ever fired on legacy values, and always passed otherwise |
| `renderColumnPages`, `isTwoColumn`, `isSidebar`, column pagination + measure refs in `preview.tsx` | unreachable |
| `layout`/`showIcons` from the Typst serialiser, the API's metadata normaliser, the seed and the marketing sample | followed the type |

`preview.tsx` loses ~150 lines of dead branching.

## Backward compatibility

`resumeSettingsSchema` is a non-strict `z.object`, so a stored resume that still carries `layout: "sidebar"` parses fine and the key is dropped. Nothing migrates and nothing breaks.

## Marketing copy

`History` said "Diff any two and restore any one". The panel diffs a selected version against **the current document**; you cannot pick version 3 and version 7 together. Now: "Compare any version with what you have now, and restore it in one click."

## Tests

`test/preview-matches-exporter.test.ts` was rewritten. It previously pinned the compromise — `const isTwoColumn = false`, `<SelectItem value="single-column">`, and "still accepts the legacy values" — which is a test protecting a bug. It now asserts the fields and branches are **absent**, and that no `.typ` reads `showIcons` or a layout branch.

Two other tests used `layout: "sidebar"` as a convenient way to manufacture a parse error; they now use a real one (mixed date shapes), so they test the engine rather than the fixture.
