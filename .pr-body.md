## What

The hero's right-hand panel is the page's entire proof: "this is the text a parser reads out of the PDF." It was a hand-written array:

```tsx
/** One `key: value` line per experience field, in schema order. */
const EXPERIENCE_TEXT = [
	{ key: "startDate", value: "March 2022" },
	{ key: "highlights", value: "• Cut p99 checkout latency 41% …" },
];
```

with a doc comment claiming it showed "the same `key: value` lines the exporter writes".

That was true once. It stopped being true when the plain-text exporter was fixed (in #218) to stop leaking internal field names — so the most prominent panel on the site was advertising `startDate: 2020-09` and `highlights: A,B` as the product's output, months after the product stopped producing it.

## Fix

`src/components/marketing/sample-resume.ts` is now one canonical `Resume` for the sample document, and the hero renders `buildPlainText(SAMPLE_RESUME)` — **the same function the export button calls**. It is a server component, so this runs once at build time and still ships no client JS.

What the panel renders now:

```
Avery Chen
Senior Backend Engineer

Email: avery@chen.dev
Phone: +49 30 555 0142
Location: Berlin
GitHub: github.com/averychen

==================================================
Work Experience
==================================================

Senior Backend Engineer
Mar 2022 - Present • Northwind Systems
- Cut p99 checkout latency 41% by rewriting the reservation path …
```

This matches the document panel beside it: same name, same role, same date range, same bullet. The `- ` marker is deliberate and documented in `text.ts` — it is the glyph the research says parses, and showing the difference between the rendered bullet and the text-layer bullet is the point of the pairing.

Also switched `overflow-x-auto` → `whitespace-pre-wrap break-words`; the long bullet was being clipped at the panel edge.

## Test

`test/marketing-claims.test.ts` previously pinned the *constant* rather than the output. It now asserts:

- the hero imports `buildPlainText` and calls it on `SAMPLE_RESUME`;
- the rendered HTML contains the exporter's rule, the template's date range (`Mar 2022 - Present`, not a stored `YYYY-MM`), and a `- ` bullet;
- the rendered HTML contains **no** `startDate:` or `highlights:`.

The last two are the regression. `html` is produced by `renderToStaticMarkup(MarketingHome)`, so these are assertions on real output, not on source text.
