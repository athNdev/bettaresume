## Build

Implement the research's archetypes, differentiated by **structure and density**, never by decorative colour. Research §7 proposes roughly:

| id | name | for | what the layout does |
|---|---|---|---|
| `academic` | Academic CV | research, postdoc, faculty | publications list, research statement, teaching, grants; looser leading; 1in margins; 2 pages acceptable |
| `compact` | Compact one-page | early career, dense content | tightest spacing band, smallest safe type (still ≥10pt), maximises content per page |
| `standard` | Standard professional | most applications | the default; balanced density |
| `technical` | Technical / engineering | IC engineering roles | skills and technologies surfaced prominently, project-centric |
| `executive` | Executive summary-first | senior leaders | summary-first, achievement-led, larger name block, generous whitespace |
| `graduate` | Graduate / entry | students and new grads | education-first, projects, coursework, one page |

Decide the final set yourself — the research's rationale is your guide. **6 is the target; fewer is fine if you can defend it, more is not.**

Each archetype must be:
- A real `.typ` file, not a config variant of another one, where the structure genuinely differs. Where the difference is only density, use a config knob on a shared base — but say which is which.
- Differentiated by **structure and density**. No coloured headings, no section background fills, no icons in headings, no tinted badges. Those were deliberately removed and the research says why.
- Compiled through the same pipeline, with the same single-column text-layer guarantee.
